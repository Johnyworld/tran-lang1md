# 배포 전 체크리스트 — 원본과 다른 것 중 "번역이 아닌" 것 전부

이 문서는 **번역이 아닌 변경**만 모은다. 마지막에 여기 적힌 것만 처리하면 배포판이
된다. 번역 인프라(훅·글리프 테이블·코드 페이지·풀 재배치)는 배포판에 그대로 남아야
하므로 여기 없다.

원칙 두 가지.

- **디버그용은 배포 빌드에 넣지 않는다.** 파일을 따로 뽑는다.
- **배포 빌드에 남는 예외는 이 문서에 전부 적고 기계가 검사한다.**

## 1. 체크섬 우회 — 배포 빌드에 남아 있다 ⚠️

```
0x18E = 0000    헤더 체크섬. 0 이면 0x4630 의 검사 루틴이 비교를 건너뛴다
```

작업 중에는 매 빌드 재계산이 번거로워 우회를 쓴다. 우회를 빠뜨리면 원인 불명의
빨간 화면을 보게 되므로 개발 중 기본값이 우회다.

**배포판은 정상 체크섬으로 빌드한다.**

```
python3 tools/build_all.py --release     # 0x200..끝 워드 합을 0x18E 에 기록
```

`--release` 는 디버그 표식(아래 3번)이 있으면 빌드를 거부한다.

## 2. 롬 확장 1MB — 배포판에도 남는다 (정상)

```
0x1A4 = 000FFFFF   롬 끝 주소
```

대본과 우리 테이블을 넣을 자리가 원본에 0바이트였다. 확장은 번역 인프라이므로
되돌리지 않는다. 실기·에뮬 모두 문제없음이 확인됐다.

## 3. 디버그 롬 — 배포 빌드와 파일이 다르다

```
python3 tools/debug_rom.py [--weak-enemy]   ->  work/korom_debug.md
```

`work/korom_all.md` 에는 **들어가지 않는다.** 디버그 롬은 헤더 노트 필드에 표식을
남기므로 어느 파일이 무엇인지 나중에도 구분된다.

```
0x1C8  "DEBUG BUILD - NOT FOR RELEASE"     헤더 노트 (게임 동작과 무관)
```

바꾸는 자리는 **클래스 스탯 표 + 코드 한 바이트**다.

| 자리 | 원본 | 디버그 | 효과 |
|---|---|---|---|
| 클래스표 1..33 `+06` AT | 클래스별 | 99 | 한 방에 죽인다 |
| 클래스표 1..33 `+08` DF | 클래스별 | 99 | 안 죽는다 |
| 클래스표 1..33 `+04` MP | 클래스별 | 99 | 마법 무제한 |
| 클래스표 1..33 `+0A` MV | 클래스별 | 99 | 맵 끝까지 한 턴에 (40 은 지형 비용 때문에 모자랐다) |
| 클래스표 1..33 `+70` 지휘범위 | 클래스별 | 8 | 용병 통제 범위 |
| 클래스표 1..33 `+7C` 문턱/8 | 파이터 2 등 | 0 | **한 마리 잡으면 레벨업** |
| 코드 `0x0D4D5` 전직 레벨 조건 | `0A` (레벨 10) | `01` | **레벨 1부터 전직 팝업** |
| (`--weak-enemy`) 34..62 AT/DF | 클래스별 | 1 | 적이 약해진다 |
| (`--force-popup=X`) 코드 `0x10528` | `0003094A` | 창 레코드 주소 | "마법을 못 씁니다" 자리에 레벨업/전직 창을 띄운다 |

즉 디버그 롬에서는 적 한 마리로 레벨이 오르고, **스테이지를 클리어하면** 정산에서
레벨업 팝업 → 1.5초 뒤 전직 팝업이 뜬다.

**확인은 스테이지를 끝내야 한다.** 레벨업·전직 창은 정산 시퀀스(`0x1CC20` ->
`0xD372`)에서 돌고 전투 중에는 창이 아니라 연출만 나온다. 스테이지 1 은 승리 조건이
"레딘의 탈출(맵 끝으로)" 이라 적을 안 잡아도 끝나며, 문턱 0 이면 EXP 0 으로도
레벨업 판정이 성립한다.

되돌리는 방법: **되돌릴 것이 없다.** `work/korom_debug.md` 를 지우면 끝이고 배포
빌드는 애초에 영향받지 않는다. 다만 코드 한 바이트를 건드리므로 표 비교만으로는
안 잡혀서, `release_check.py` 의 `CODE_SITES` 에 그 주소를 적어 두었다. **디버그
항목을 늘리면 그 목록에도 한 줄 추가할 것.**

## 4. 번역하지 않기로 결정한 것 (되돌릴 것 없음)

배포판에 원문으로 남는다. 결정 근거는 STATUS 참고.

```
PLAYER / ENEMY / FRIENDLY / VS      영어 라벨
Yes / No / ON / OFF / BGM           영어 라벨
NEW GAME / LOAD GAME / CONTINUE     영어 라벨
Scenario / Sound / Small Map / TURN 영어 라벨
A+ / D+ / HP / MP / AT / DF / MV / LV / ITEM / Pts
030A1A 메뉴                         어느 글리프 풀과 짝인지 미확정
```

## 5. 배포 전 검사

```
python3 tools/build_all.py --release
python3 tools/uiscan.py                 # 남은 일본어 목록이 의도한 것만인지
python3 tools/release_check.py          # 아래 항목을 기계가 확인한다
```

`release_check.py` 가 보는 것:

- `0x18E` 가 실제 워드 합과 일치하는가 (우회가 남아 있지 않은가)
- 헤더 노트에 디버그 표식이 없는가
- 클래스 스탯 표가 원본과 바이트 단위로 같은가 (강화·문턱이 새지 않았는가)
- `CODE_SITES` 의 코드 바이트가 원본과 같은가 (전직 레벨 조건, 팝업 즉치)
  — **길이까지 비교한다.** 한 바이트만 보던 때 `0x31020 -> 0x32A8E` 를 놓쳤다
  (앞 두 바이트가 같다)
- `0x1A4` 가 1MB 끝인가
